## 1. “上线”的定义（默认口径，待确认）

1. **无 501 的核心链路**：食记、排餐、做饭扣库存、媒体图片全部真实可用。
2. **Release 级安装包**：release 签名、versionName/versionCode、R8/混淆验证、可重复构建。
3. **可部署后端**：Docker Compose 一键起（Postgres + server），HTTPS/反向代理、环境变量管理、健康检查、备份说明。
4. **数据安全与隐私**：密钥不落库/不提交；换账号清缓存；家庭成员数据隔离；删除/退出后果明确。
5. **真实设备验证**：手机尺寸 + 小米平板（宽窄窗口、横竖屏、键盘、大字体），两/三账号共享与权限矩阵。
6. **可交付材料**：安装包、部署文档、测试证据（截图/日志/命令）、演示数据脚本。

> 已确认（2026-11-26）：目标是 **LMO 交作业 + 现场演示**，不做应用商店分发；因此不需要商店合规、隐私政策、崩溃上报平台和公网 SLA。后端运行在演示电脑上，平板通过局域网地址或 USB 反向转发访问；不要求公网 HTTPS 域名（本地地址需与平板设备核对）。

## 4. 风险与决策点

1. **“上线”形态未定**：LMO 交付 vs 公开分发；若公开，需要商店合规、隐私政策、账号删除、崩溃上报、HTTPS 域名。
2. **文档与最新用户决策冲突**：方案 §4 要求宽屏左侧导航；组员按用户要求改为“始终底部导航”。默认按**最新用户决策**执行（底部导航 + 宽屏内容双栏），待确认。
3. **做饭扣库存的原子性与并发**：必须同事务 + 幂等键 + 版本检查；需专门测试并发。
4. **后端托管**：当前演示依赖本机 8080 + 手机模拟器；平板需局域网/HTTPS 可达地址，涉及域名与证书决策。
5. **数据语义**：食记=实际摄入（个人）、做饭=家庭事件、计划≠记录；任何实现不得混淆（`docs/PRODUCT_RULES.md` 为准）。
6. **范围控制**：首版不做拍照识菜、营养库、社交、多家庭、离线合并；不新增不必要依赖。
