## 开场视频的实现细节

- 原始桌面 MP4 保持原样，不覆盖、不移动。处理后文件位于
  `app/src/main/res/raw/app_cat_intro.webm`，APK 只包含处理后的静音版本。
- 从原 720×960 画面提取中央动画区域 `(x=50,y=280,width=620,height=540)`，去掉外侧空白，
  保留小猫、星星、地面线和逐步出现的 CIVA 字样。没有重排动作或变更帧率。
- 视频的浅灰/白色外部背景按边界连通区域替换成棕色；闭合轮廓内的白脸、围裙和字母填色保留。
  页面基准棕色按 Android 解码背景对齐；播放中复用一张 16×16 Bitmap 取视频左上角纯背景色，
  同步开场与系统栏背板，处理设备/帧间 YUV 转 RGB 的细微差异，避免方形底板。
- 首次 H.264 测试在此 API 37.1 模拟器的 `c2.goldfish.h264.decoder` 出现 bufferpool 解码错误。
  最终改为平台支持的 VP8/WebM，无额外运行时依赖。支持范围依据
  [Android 官方媒体格式表](https://developer.android.com/media/platform/supported-formats)。
- 播放使用 Android `MediaPlayer` + `TextureView`，原音轨已从媒体文件删除，播放器也设为静音。
  播放约 3 秒时，单独通过既有 `MeowSound` 播放 `civa_meow.ogg` 并显示“喵”气泡。
- 收到播放完成事件后用 220ms 淡出，再进入原有 1100ms 欢迎页入场。退出登录只显示短入场，
  不重复视频。页面重建保存播放位置与已叫状态，离开窗口暂停，销毁时释放播放器、Surface 和声音。
- `CivaIntro` 日志只记录 `video_started`、`video_completed`、`video_fallback`，不记录账号或文件内容。
  若某设备无法解码，短暂展示备用长帽猫再进入登录，避免卡死；不能把这个降级画面当成视频播放成功。

## 模块边界与兼容性

- `core-ui`：欢迎布局和三项共享色，五个插画资源。旧 `ChefCatView` 仍保留，避免破坏其他调用方，
  新页面不再强制把图片转换成 Canvas 角色。
- `app`：本地视频资源、播放器、入场状态保存和系统栏底色；仍为原单 Activity 和原导航。
- `feature-bd`：普通/宽屏 home XML 同步改图并删两句说明；同步删除 BdHomeLayout 对已删除 caption 的访问，
  防止删 XML 后在测量阶段空引用闪退。排餐卡片大小和持久化逻辑不变。
- `feature-ac`：只调整菜谱列表头部 XML，原来源、搜索、收藏与详情回调不变。
- `feature-ef`：资料卡装饰图、地球按钮、默认头像、语言标题/字号；账号名称、照片、私有目录存储和后端接口不变。
- 没有新增依赖、权限、API 或数据库迁移；没有修改生成代码，也未将 API Key 写进任何素材/源码。
  所有修改文件及 SHA-256 见 [CAT_REFRESH_CHANGELOG.md](CAT_REFRESH_CHANGELOG.md)。
