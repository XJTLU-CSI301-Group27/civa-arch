# IC-20261123-CATALOG-01 公共菜谱目录（只读）

类型：NORMAL
状态：IMPLEMENTING
提出组及负责人：A（菜谱），EF 负责契约决策
提出时间（带时区）：2026-11-23T20:10+08:00
基线 commit：ae60b66（分支基线；本次契约基于 1190840 增量）

## 涉及 operationId / schema

- `listCatalogRecipes`：`GET /api/v1/recipe-catalog`（q / category / tag / highProtein / page / size）
- `getCatalogRecipe`：`GET /api/v1/recipe-catalog/{recipeId}`
- schema：`CatalogRecipe`、`CatalogRecipePage`、`CatalogRecipeIngredient`
- 复用既有错误语义（400/401/403/404/429/500/501/503）

## 原需求及复用现有接口的评估

产品要求内置菜谱（A 组 1093 道 + BD 组 312 道合并）放在服务端，菜谱内容不随设备变化。
现有 `recipes` 表要求 `household_id NOT NULL` 且食材必须引用标准食材 ID，无法承载"公共只读、
自由文本食材、保留 A 组富字段"的目录；把 7507 条自由食材映射到标准食材库成本极高且易错。
因此新增独立的只读目录资源与两个读取操作，不修改任何既有 operation/schema。

## 旧接口与新接口

- 旧：客户端读取本地 assets（A 的 `ac_recipes.json` / BD 的 `recipes/catalog.json`）。
- 新：服务端只读目录；内置食材保持自由文本（展示用），只有家庭菜谱（后续阶段）才引用标准食材 ID。
- 目录在服务端以固定种子导入（迁移文件），无写接口、无缓存失效问题。

## 影响调用方、数据库、缓存及 UI

- 客户端：菜谱 Tab 从 API 读取并做只读缓存；今天页推荐池改为公共目录（BD 本地目录退役）。
- 数据库：新增 `recipe_catalog` 表（无外键、无用户数据）。
- 缓存：客户端只做只读缓存，不写回服务端；离线可看已缓存页。

## 兼容性判断及未验证项

- 兼容：纯新增；既有 43 个操作未改动（已逐 operation 对比）。
- 未验证：真实设备上的大列表滚动性能（目录约 1200 条，分页 20/页）。

## 决定

采用：新增只读目录接口。决定者：项目负责人（2026-11-23 计划评审通过 P1）。

## 迁移与回退计划

- 迁移：`recipe_catalog` 建表 + 种子数据；可重复生成（id 由名称哈希确定）。
- 回退：删除两个 operation 与表，客户端退回本地 assets 读取。
